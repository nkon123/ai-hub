# MCP 서버 만들어 Desktop에 붙이기 — 연구회원 가이드

내가 만든 도구(MCP 서버)를 **AI Asset Hub 데스크톱**에 붙여, 대화에서 AI가 필요할 때 골라 쓰게 하는 방법이다.
Python 파일 하나면 된다. 허브 승인 없이 내 PC에서 바로 써 볼 수 있다.

- 대상 버전: 데스크톱 **0.1.9 이상** (서버 직접 추가는 0.1.4부터, 여러 도구를 한 질문에 쓰는 것은 0.1.8부터)
- 동작하는 예제: [`samples/mcp-servers/glossary-mcp/server.py`](../../samples/mcp-servers/glossary-mcp/server.py) — 복사해서 시작하면 된다.

## 0. 데스크톱 클라이언트 설치

- 다운로드: **[최신 릴리스 페이지](https://github.com/nkon123/ai-hub/releases/latest)** → Assets의 `AI.Asset.Hub.-Setup-<버전>-x64.exe`
- Windows x64 설치 파일이며, 설치본에 필요한 실행 환경(agent-runtime)이 함께 들어 있다.
- 코드 서명이 없어 **Windows Smart App Control/애플리케이션 제어가 실행을 막을 수 있다.** 막히면 관리자에게 문의한다.
- 대화에는 접근 가능한 **Ollama**와 설치된 채팅 모델이 필요하다. 주소와 모델은 앱의 설정 화면에서 지정한다.

## 1. 어떻게 동작하나

```
사용자 질문 ──▶ AI가 등록된 도구 중 필요한 것을 고름 ──▶ (매번 확인) ──▶ 내 서버가 실행됨 ──▶ 결과로 AI가 답변
```

- AI는 도구의 **이름·설명·입력 형식**만 보고 고른다. 코드는 보지 않는다.
- 내 서버는 호출할 때마다 **새 프로세스로 뜬다**. 상태를 메모리에 들고 있을 수 없다(파일·DB에 저장).
- 한 질문에서 여러 도구가 필요하면(예: "메일 가져와 그리고 현재 시간 알려줘") **최대 3개까지 순서대로** 호출한다.

## 2. 5분 만에 붙여 보기

1. 준비: Python과 `mcp` 패키지가 있는 개발 환경에서 예제를 확인한다.
   ```bash
   pip install "mcp>=2.2.0"
   python samples/mcp-servers/glossary-mcp/server.py --list-tools
   python samples/mcp-servers/glossary-mcp/server.py --call glossary.lookup --args '{"term": "PoC"}'
   ```
   도구 목록과 답이 나오면 서버 코드는 정상이다. (인자 없이 실행하면 서버로 떠서 입력을 기다린다 — 정상이다.)
2. 데스크톱 앱에서 **자산 허브 → MCP 서버** 탭 → **서버 추가**.
3. 종류 **로컬 Python 파일** → **파일 선택**으로 `server.py`를 고른다.
4. **이름**을 영문 소문자·숫자·`-`로 적는다 (예: `glossary`).
5. **연결 시험**을 누르면 서버가 뜨고 도구 목록이 나온다. 쓸 도구와 **매번 확인** 여부를 고른다.
6. **도구 N개로 추가**. 상태가 `ACTIVE`이면 끝이다.
7. 대화 화면 입력창의 **+ 메뉴 → 도구**에서 자동 선택이 켜진 것을 확인하고 묻는다: "PoC가 뭐야?"

## 3. 서버를 만들 때 지킬 것

| 규칙 | 이유 |
|---|---|
| 표준 라이브러리 + `mcp`만 쓴다 | 데스크톱에 동봉된 Python으로 실행된다. `pip install`을 하지 않는다 |
| 환경변수를 읽지 않는다 | 서버는 환경변수 없이(`env={}`) 뜬다. 토큰·주소는 코드에 넣지 말고, 필요하면 설정 파일을 폴더에 두고 읽는다 |
| `print()`로 아무것도 찍지 않는다 | stdout은 통신 채널이다. 로그는 `sys.stderr`로 |
| 폴더는 **50MB·파일 2,000개 이하** | 고른 파일이 있는 **폴더 전체**가 복사되어 실행된다(`.venv`·`__pycache__`·`.git` 제외) |
| 읽기 전용으로 만든다 | 이 PoC의 도구는 조회만 한다. 파일 삭제·전송·수정 도구는 만들지 않는다 |
| 인자 없이 실행하면 서버, 인자가 있으면 점검 | 예제의 `--list-tools`, `--call` 구조를 유지하면 앱에 붙이기 전에 터미널에서 확인할 수 있다 |

핵심 골격 (예제에서 발췌):

```python
async def on_list_tools(ctx, params):
    return types.ListToolsResult(tools=[
        types.Tool(
            name="glossary.lookup",                       # <서버이름>.<동작>
            description="사내 용어의 뜻을 찾습니다. '~가 뭐야' 같은 질문에 씁니다.",
            input_schema={...},                           # JSON Schema
            annotations=types.ToolAnnotations(read_only_hint=True),
        ),
    ])

async def on_call_tool(ctx, params):
    ...                                                   # params.name, params.arguments
    return types.CallToolResult(content=[types.TextContent(type="text", text="결과")])
```

## 4. AI가 내 도구를 잘 고르게 하려면

작은 로컬 모델이 고르므로 **글이 곧 성능**이다. 실제로 아래 때문에 도구가 안 골라지거나 엉뚱하게 골라진 적이 있다.

- **이름은 `서버이름.동작`으로 짓는다** (`glossary.lookup`, `outlook.list_messages`). 앞부분(서버이름)이 같은 도구끼리 묶여 서버마다 따로 판단된다. 서버끼리 앞부분이 겹치지 않게 한다.
- **설명은 한 줄, 160자 이내.** 무엇을 하는지 + 어떤 질문에 쓰는지를 사용자가 실제로 쓰는 말로 적는다. 넘치면 잘린다.
  - 나쁨: `데이터 처리`
  - 좋음: `Outlook 메일을 날짜 범위로 가져옵니다. '오늘 메일', '최근 3일 메일' 같은 요청에 씁니다.`
- **필수 인자는 최소로.** 사용자가 말하지 않을 값(id, 스키마명 등)을 필수로 두면 AI가 지어내거나 호출이 거부된다. 모르면 생략해도 동작하는 기본값을 두고, 필수가 필요하면 설명에 "사용자가 말한 ○○"라고 쓴다.
- **다른 도구의 결과가 있어야 부를 수 있는 도구**(예: 목록의 id로 본문 조회)는 한 질문 안에서 이어서 호출되지 않는다. 한 도구가 필요한 정보를 스스로 조회하게 만든다.
- **날짜는 `YYYY-MM-DD` 형식**을 스키마의 `pattern`으로 강제하고, "최근 N일" 같은 대체 인자(`days`)를 함께 둔다. 모델이 '오늘'이라고 써 넣으면 호출이 거부된다.
- **못 찾은 것은 오류가 아니라 정상 결과**로, 말로 돌려준다 (`'zzz'은(는) 용어집에 없습니다.`). AI가 그대로 읽고 답한다.
- 요약·번역·정리는 도구가 아니다. 도구는 **가져오는 것**까지만 하고 나머지는 AI가 답변에서 한다.
- 시험용 도구를 켜 둔 채로 두지 마라. `hello.echo` 같은 도구가 켜져 있으면 "요약해줘" 같은 질문에 끼어들 수 있다.

## 5. 안전과 확인

- 이 서버는 **내 PC에서 내 권한으로** 실행된다. 출처가 불분명한 코드는 추가하지 않는다.
- 도구는 기본 **매번 확인**이다. 실행 전 확인 창이 뜬다. 조회 전용이고 신뢰하는 도구만 도구별로 해제한다.
- 코드·대화·로그에 **비밀번호, 토큰, 개인정보, 실제 업무 DB 접속 정보**를 넣지 않는다. 시험 데이터는 가짜 값으로 만든다.
- 서버가 도구를 바꾸면(추가·삭제·스키마 변경) 앱이 기존 등록과 어긋났다고 거부한다. **삭제 후 다시 추가**한다.

## 6. 고친 뒤 반영하기

원본 파일을 고쳐도 앱이 쓰는 것은 추가할 때 만든 **복사본**이다. 반영하려면 **MCP 서버 탭에서 삭제 → 다시 서버 추가**를 한다(원본 파일은 지워지지 않는다).

## 7. 문제가 생겼을 때

| 증상 | 확인 |
|---|---|
| 대화에서 `MCP Tool 이 오류를 반환했습니다: …` 가 뜬다 | 뒤의 문장이 서버가 직접 알려 주는 원인이다(예: `repos.json 이 없습니다`). 설정 파일이 필요한 서버(git-repo 등)는 **폴더에 설정 파일을 만든 뒤** 추가해야 한다 — 서버는 폴더를 복사해 실행하므로, 파일을 만들거나 고친 뒤에는 삭제 후 다시 추가한다 |
| 연결 시험이 실패한다 | 터미널에서 `python server.py --list-tools`가 되는지. 안 되면 코드 문제다. `print()`를 찍지 않았는지, `mcp` 외 패키지를 쓰지 않았는지 |
| 추가는 됐는데 대화에서 도구를 안 쓴다 | MCP 서버 탭에서 `ACTIVE`인지 → 입력창 **+ → 도구**에서 자동 선택이 켜져 있고 내 서버가 범위에 있는지 → 설명이 사용자 말투와 맞는지(4장) |
| 다른 도구가 대신 골라진다 | 두 도구의 설명이 겹치는지. 이름 앞부분(서버이름)이 같은지 |
| 여러 도구를 요청했는데 하나만 실행된다 | 뒤 도구가 필요로 하는 값을 질문에서 알 수 없어 거부됐을 수 있다(필수 인자 줄이기). 한 질문에 최대 3개다 |
| `MCP_PERMISSION_DENIED` | 서버 추가 화면이 만드는 권한 설정은 이 PC의 사용자 역할로 자동 지정된다. 계속 나오면 삭제 후 다시 추가 |
| 응답이 느리다 | 서버(이름공간)가 2개 이상이면 도구 선택 호출이 서버 수만큼 늘어난다. 쓰지 않는 서버는 삭제한다. 첫 질문은 모델을 불러오느라 더 걸린다 |

## 8. 더 나아가기

- **HTTP 서버**: 이미 다른 곳에서 돌고 있는 MCP 서버라면 종류를 **HTTP 주소**로 하고 주소를 넣는다. 이 PC 밖 주소는 경고가 표시된다.
- **동료와 공유**: 지금은 폴더(`server.py`)를 저장소로 공유하고 각자 위 2장대로 추가한다. 허브에 등록해 승인·배포하려면 매니페스트가 필요하며 [`docs/mcp-server-authoring-prompt.md`](../mcp-server-authoring-prompt.md)를 AI 코딩 도구에 붙여 쓴다.
- **AI 코딩 도구로 만들기**: 예제 `server.py`를 통째로 주고 "이 구조를 유지하면서 ○○를 조회하는 읽기 전용 도구를 만들어 줘. 표준 라이브러리와 mcp만 쓰고 print는 쓰지 마"라고 요청하면 된다.
