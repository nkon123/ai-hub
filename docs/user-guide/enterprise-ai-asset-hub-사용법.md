# Enterprise AI Asset Hub 사용법 — Portal부터 Desktop까지

이 문서는 Knowledge(지식 자산)를 **Portal에 등록**하고, **승인**받아, **Desktop
Client로 내려받아 설치**하고, 실제로 **대화에서 검색되게** 만드는 전 과정을
순서대로 설명합니다.

핵심 개념 하나를 먼저 잡고 가면 나머지가 쉽습니다.

> **"설치됨"과 "활성화됨"은 다릅니다.**
> Desktop에 자산이 설치되어도, 검색 엔진에 등록되기 전까지는 대화에서 쓰이지
> 않습니다. 이 문서의 5단계가 그 등록입니다.

---

## 전체 흐름 한눈에 보기

| 단계 | 어디서 | 무엇을 |
|---|---|---|
| 1 | Portal | 문서를 올려 Knowledge 등록 |
| 2 | Portal | 색인(인덱싱) 완료 확인 |
| 3 | Portal | 검토·승인 |
| 4 | Portal | 반출 준비 점검 → ZIP 생성 |
| 5 | Desktop | 설치 → **활성화** |
| 6 | Desktop | 대화에서 검색 |

각 단계는 앞 단계가 끝나야 진행됩니다. 건너뛰면 뒤에서 막히는데, **어디서 왜
막혔는지 화면이 알려주도록** 만들어져 있습니다.

---

## 0. 시작 전 준비

### 서비스 기동

macOS 개발 환경에서는 스크립트 하나로 전부 띄웁니다.

```bash
scripts/macos/dev-stack.sh start      # 8개 서비스 + Desktop
scripts/macos/dev-stack.sh status     # 상태 확인
```

`status`는 각 서비스가 **실제로 응답하는 커밋**을 저장소 HEAD와 나란히
보여줍니다. 코드를 고쳤는데 동작이 안 바뀐다면 여기서 먼저 확인하세요 —
오래된 프로세스가 그대로 떠 있는 경우가 흔합니다.

| 서비스 | 포트 | 역할 |
|---|---|---|
| portal-api | 8000 | 자산 등록·검토·배포 |
| portal-web | 3000 | Portal 화면 |
| agent-runtime | 8100 | 대화 실행 |
| indexing-runtime | 8200 | 색인 생성 |
| search-runtime | 8300 | 지식 검색 |
| distribution-service | 8400 | ZIP 생성 |
| office-mcp-server | 8500 | MCP Tool |
| Ollama | 11434 | 로컬 LLM (별도 설치) |

### 필요한 모델

```bash
ollama pull exaone3.5:7.8b        # 답변 생성
ollama pull qwen3-embedding:0.6b  # 색인·검색 임베딩
```

## 1. Knowledge 등록 (Portal)

`http://localhost:3000` → **자산** → **Knowledge 등록**

입력하는 것:

| 항목 | 설명 |
|---|---|
| 지식 이름 | 목록과 검색에서 보이는 이름 |
| 설명 | 이 지식이 무엇을 다루는지 |
| 보안 등급 | `PUBLIC_INTERNAL` / `INTERNAL` / `CONFIDENTIAL` |
| 문서 파일 | 현재 Markdown(`.md`) |

**보안 등급을 신중히 고르세요.** 검색은 요청자의 권한 등급이 문서 등급을
포함할 때만 결과를 돌려줍니다. 예를 들어 `CONFIDENTIAL`로 등록하면 기본
권한(`INTERNAL`)으로는 **아무것도 검색되지 않습니다** — 오류가 아니라 정책상
차단이며, Portal의 검색 품질 테스트가 그 사실을 이유와 함께 알려줍니다.

---

## 2. 색인 확인 (Portal)

등록하면 색인이 자동으로 시작됩니다. 자산 상세 화면에서 상태를 봅니다.

| 상태 | 뜻 |
|---|---|
| `RUNNING` | 진행 중 |
| `COMPLETED` | 완료 — 청크 수가 함께 표시됩니다 |
| `FAILED` | 실패 — **사유가 함께 기록됩니다** |

실패 사유의 예: `indexing-runtime 응답이 설정된 대기 시간(300초) 안에 오지
않아 색인 작업을 실패로 처리했습니다(ReadTimeout).`

문서가 크면 시간이 오래 걸립니다. 반복해서 시간 초과가 나면 문서를 나누거나
`PORTAL_INDEXING_RUNTIME_TIMEOUT_SECONDS`를 늘립니다.

> **색인이 실패한 Knowledge는 이후 단계로 갈 수 없습니다.** 검색할 수 없는
> 지식을 배포하는 것은 의미가 없기 때문에, 4단계에서 반출 자체가 거부됩니다.

### 검색 품질 테스트 (권장)

승인 전에 실제로 질문을 던져 어떤 내용이 검색되는지 확인할 수 있습니다.
LLM 답변이 아니라 **검색 계층**을 보는 도구라, 근거가 제대로 잡히는지 판단할
때 씁니다.

결과가 0건이면 이유를 구분해서 알려줍니다:

- **색인이 없음** — 2단계로 돌아갑니다
- **보안 등급 차단** — 자산 등급이 검색 권한보다 높습니다
- **관련도 임계값** — "관련도 필터 없이 다시 검색"으로 확인할 수 있습니다

## 3. 검토와 승인 (Portal)

등록 직후 버전은 `DRAFT`입니다. 검토를 거쳐 `APPROVED`가 되어야 배포할 수
있습니다. 역할에 따라 할 수 있는 일이 다릅니다.

| 역할 | 개발용 토큰 | 주요 권한 |
|---|---|---|
| CREATOR | `dev-user-token` | 등록·수정·검토 요청·**배포 요청** |
| TECH_REVIEWER | `dev-reviewer-token` | 기술 검토 승인/반려 |
| SECURITY_REVIEWER | `dev-security-token` | 보안 검토 |
| RELEASE_MANAGER | `dev-release-token` | 릴리스 승인·수명주기 |
| ADMIN | `dev-admin-token` | 전체 |

> 이 토큰들은 PoC용 고정 값이며 실제 인증이 아닙니다. 플랫폼이 신원을
> **주장**할 뿐 검증하지 않습니다.

**승인된 버전은 수정할 수 없습니다.** 내용을 바꾸려면 새 버전을 올립니다 —
이미 배포된 것과 손에 있는 것이 달라지는 상황을 막기 위해서입니다.

## 4. 반출 준비 점검과 ZIP 생성 (Portal)

자산 버전 화면에서 **반출 준비 상태**를 먼저 확인합니다. 이 점검은 "이
Knowledge가 Desktop에 설치된 뒤 실제로 검색될 수 있는가"를 미리 판정합니다.

| 검사 | 실패하면 |
|---|---|
| 색인 완료 | 2단계로 |
| 색인 디렉터리 존재 | 재색인 필요 |
| 색인 식별자 일치 | 잘못된 색인을 가리킴 |
| BM25 형식 | `convert-bm25-format`으로 변환 필요 |
| 벡터 저장소 존재 | 색인 불완전 |
| 임베딩 모델 기록 | 경고 — 반출은 가능 |
| 보안 등급 기록 | 경고 — `stamp-classification` 권장 |

**실패(FAIL)가 하나라도 있으면 ZIP 생성이 거부됩니다.** 경고(WARN)는 막지
않습니다. 거부될 때는 어떤 검사가 왜 실패했고 무엇을 하면 되는지 함께
표시됩니다.

점검을 통과하면 ZIP을 만들고 내려받습니다. 이 파일이 Desktop으로 옮길
**Offline Bundle**입니다.

## 5. 설치와 활성화 (Desktop)

### Portal 연결 (최초 1회)

**자산 허브** → **찾아 설치** → Portal 연결 설정

| 항목 | 값 |
|---|---|
| Portal 주소 | `http://127.0.0.1:8000` |
| 식별 토큰 | `dev-user-token` |

토큰 역할에 따라 설치 가능 여부가 갈립니다. 카탈로그는 모든 역할이 볼 수
있지만, **배포 생성 권한**이 없는 역할(검토자 등)은 설치 단계에서 막힙니다.

### 설치

**찾아 설치**에서 자산을 고르면 15단계 안전 검증을 거쳐 설치됩니다 — 격리
영역 복사, 경로 안전성, 중첩 압축 금지, 실행 파일 정책, 체크섬, Manifest
검증, 회수 목록 대조 등.

`ZIP 가져오기` 탭으로 파일을 직접 넣을 수도 있습니다.

### 활성화 — 이 단계를 빠뜨리면 검색되지 않습니다

설치가 끝나면 자동으로 활성화를 시도합니다. **설치 성공과 활성화 성공은 별개**로
표시되며, 활성화가 실패해도 설치는 성공으로 남습니다.

| 상태 | 뜻 |
|---|---|
| 활성화됨 | 검색에 등록 완료 |
| 이미 검색 가능 | 같은 지식이 중앙 색인에 있어 등록이 필요 없음 (정상) |
| 활성화 안 됨 | 아직 시도하지 않음 |
| 활성화 실패 | 사유가 함께 표시됩니다 |

자주 보는 실패 사유:

- **활성화 API 없음(404)** — search-runtime이 오래된 프로세스입니다. 재시작하세요.
- **활성화 기능 꺼짐** — search-runtime에 `SEARCH_LOCAL_INDEX_ROOTS`가 설정되지
  않았습니다. Desktop 설치 경로를 허용 목록에 넣어야 합니다.
- **index 폴더 없음** — 색인 없이 배포된 자산입니다. 다시 설치해도 같습니다 —
  Portal에서 색인 상태를 확인하세요.
- **legacy 형식** — 색인이 옛 형식이라 등록이 거부됩니다. `convert-bm25-format`
  변환 후 다시 반출하세요.

search-runtime을 Desktop과 같은 PC에서 띄울 때는 설치 경로를 허용해야 합니다:

```bash
SEARCH_LOCAL_INDEX_ROOTS="$HOME/Library/Application Support/desktop-client/assets" \
  scripts/macos/dev-stack.sh restart search-runtime
```

## 6. 대화에서 사용 (Desktop)

**채팅** 화면에서 **지식에서 검색**을 켜면 활성화된 Knowledge가 검색 대상이
됩니다.

### 지식 자동 선택

설치된 Knowledge가 여러 개면, 질문과 각 지식의 이름·설명·태그를 보고 관련
있는 것만 골라 검색합니다. 진행 상황이 단계로 표시됩니다:

```
관련 지식을 찾고 있습니다 → 관련 지식에서 항목을 추출하고 있습니다 → 답변을 작성하고 있습니다
```

선택 결과도 함께 보여줍니다.

- **자동 선택함** — 어떤 지식을 왜 골랐는지
- **선택 없이 전체 검색** — 설치된 지식이 적어 고를 필요가 없었음
- **자동 선택 실패 → 전체 검색** — 선택이 실패해 전체를 검색함

세 가지를 구분해서 보여주는 이유는, "고르지 않은 것"과 "골랐는데 실패한 것"이
서로 다른 사실이기 때문입니다.

### 근거 없는 답변은 만들지 않습니다

검색 결과가 0건이면 **LLM을 호출하지 않고** "근거를 찾지 못했습니다"로
끝납니다. 지어낸 답변을 받는 것보다 낫다는 판단이며, 이 동작은 바꿀 수
없습니다.

### 허브 조회 (선택)

로컬에 근거가 없을 때 중앙 Hub에 물어볼 수 있습니다. **기본은 꺼져 있고**,
켤 때마다 사용자가 직접 켜야 합니다(세션 간 유지되지 않습니다).

> **로컬 문서 내용은 Hub로 전송되지 않습니다.** 전송되는 것은 사용자가 입력한
> 질문 원문뿐이며, 보내기 전에 미리보기로, 보낸 뒤에는 실제 전송된 질의로
> 두 번 확인할 수 있습니다. 검색 결과에는 로컬/허브 출처 배지가 붙습니다.

## 자주 막히는 곳

| 증상 | 원인 | 해결 |
|---|---|---|
| 화면이 "연결 끊김"인데 서비스는 살아 있음 | 오래된 프로세스 또는 CORS | `dev-stack.sh status`로 커밋 확인 후 재시작 |
| 답변이 항상 "근거 없음" | 보안 등급 미기록 또는 등급 차단 | Portal 검색 품질 테스트로 원인 확인 |
| 설치했는데 검색 안 됨 | 활성화되지 않음 | 설치된 자산 화면에서 활성화 상태 확인 |
| ZIP 생성이 거부됨 | 색인이 온전하지 않음 | 반출 준비 점검의 실패 항목 확인 |
| 색인이 계속 실패 | 문서가 크거나 임베딩이 느림 | 실패 사유 확인 후 문서 분할 또는 대기 시간 상향 |

## 설계상 알아두면 좋은 것

**임베딩 모델은 선택하는 값이 아닙니다.** 질의는 그 지식이 **색인될 때 사용한
모델**로 임베딩됩니다. 다른 모델로 바꾸면 검색이 오류 없이 조용히 무의미해지기
때문에, 모델을 바꾸는 것은 곧 재색인을 뜻합니다.

**거절은 조용할 수 없습니다.** 검색 결과 0건과 "이 색인은 검색할 수 없음"은
반드시 구분해 표시됩니다. 어떤 이유로든 결과가 없을 때, 그것이 정말 근거가
없어서인지 정책·설정 때문인지 화면이 알려주도록 만들어져 있습니다.

**승인된 버전은 불변입니다.** 수정이 필요하면 새 버전을 올립니다.
